> 목표: Notion 포트폴리오를 웹사이트로 옮기고, 면접관이 "이 프로젝트에서 뭘 했나요?"라고 물으면 **내가 1인칭으로 답하는** 챗봇을 붙인다.

## 1. 챗봇 LLM 구성

### 동작 규칙

| 상황 | 답변 엔진 | UI 표시 |
| --- | --- | --- |
| Mac 켜짐 (기본) | 로컬 LLM | 🖥️ "로컬 LLM이 답변 중 · {모델명} on MacBook" |
| 사용자가 "빠른 답변으로 전환" 클릭 | 호스팅 API | ☁️ "Claude Haiku 5.5가 답변 중" |
| Mac 꺼짐 또는 연결 불가 | 호스팅 API로 **자동 전환** | ☁️ + "로컬 LLM이 오프라인이라 클라우드로 답변합니다" |
| 로컬이 다른 질문 처리 중 | 로컬 대기 | "답변 대기 중…" + 전환 버튼 강조 |

- 전환 버튼은 항상 노출하고, 첫 글자가 늦게 나오면(예: 5초 이상) 버튼을 강조해 안내
- 답변 도중 전환하면 현재 답변을 중단하고 같은 질문을 호스팅 API로 다시 요청
- 메시지마다 어떤 엔진이 답했는지 작은 라벨로 남김
- 사용자가 다시 로컬로 돌아갈 수 있음 (토글)
- 패널 상단에 로컬 LLM 상태 표시: 🟢 온라인 / ⚪ 오프라인

### 아키텍처

```
[브라우저] ──▶ [Vercel: /api/chat]
                  │ engine = local | cloud
                  │ 로컬 상태 확인 (타임아웃 1~2초, 결과 30초 캐시)
                  ├─▶ 로컬 가능 → Tailscale Funnel ─▶ [Mac: 인증 프록시 ─▶ Ollama]
                  └─▶ 로컬 불가 / cloud 선택 → [Claude API (Haiku 5.5)]
                  │
                  └─ 응답 스트림 맨 앞에 메타데이터 전송 { engine, model, fallbackReason }
```

- **Ollama에는 자체 인증이 없음** → 그대로 외부에 공개하면 누구나 내 Mac의 LLM을 쓸 수 있음. Mac에 작은 인증 프록시(공유 비밀키 헤더 검사)를 두고, Funnel은 프록시만 공개
- Vercel 서버만 비밀키를 알고, 브라우저는 Mac 주소와 키를 모름
- 두 엔진의 스트림을 하나의 형식으로 맞춰서 프론트는 엔진 종류와 상관없이 같은 방식으로 렌더링

### 엔진별 컨텍스트 전략

| 엔진 | 시스템 프롬프트에 넣는 내용 | 이유 |
| --- | --- | --- |
| 로컬 LLM | 전체 프로젝트 요약 목록(짧게) + 질문과 관련된 프로젝트 1~2개 상세 | 내용이 길면 첫 글자까지 수십 초 이상 걸림 |
| 호스팅 API | 프로젝트 10개 전체 상세 (프롬프트 캐싱 적용) | 긴 내용도 빠르게 처리, 캐싱으로 비용 절감 |

- 관련 프로젝트 고르는 방법: ① 상세 페이지에서 연 채팅이면 해당 프로젝트 ② 질문에 프로젝트명·기술명이 있으면 키워드 매칭 ③ 둘 다 아니면 요약 목록만 사용
- 프롬프트 생성 함수 하나에 "분량 한도"를 파라미터로 받아서 두 엔진이 공유

### 운영 비용

| 항목 | 월 비용 |
| --- | --- |
| 로컬 LLM (모델, Ollama, Tailscale Funnel) | 0원 |
| Mac 상시 가동 전기료 (대기 5~8W, 답변 생성 시 30~60W) | 약 1,000~2,000원 |
| Claude Haiku 5.5 (전환·폴백 시에만, 질문당 약 $0.003) | 1,000회 사용해도 약 $3 |
| Vercel, Upstash | 0원 (무료 플랜) |

### Mac 운영 조건
- 잠자기 방지 (`pmset` 또는 `caffeinate`), 전원 연결 상태 유지
- 재부팅 시 Ollama, 인증 프록시, Tailscale 자동 실행 (`launchd`)
- 모델을 메모리에 계속 올려두기 (`keep_alive: -1`) → 첫 요청 지연 방지
- 동시 처리 1개로 제한 (16GB 메모리 기준)
- Mac을 들고 나가거나 덮개를 닫으면 자동으로 호스팅 API로 전환됨 → 서비스는 계속 동작

## 2. 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | Next.js (App Router) + TypeScript | SSG로 SEO/OG 해결, Route Handler로 챗봇 서버 구현 |
| 스타일 | Tailwind CSS | 기존 사용 경험 |
| 콘텐츠 | 마크다운 + frontmatter (gray-matter, zod로 검증), `react-markdown`으로 렌더링 | 화면과 챗봇이 같은 원본을 사용. 본문에 JSX가 없어 MDX 대신 일반 마크다운 사용 |
| 로컬 LLM | Ollama + 한국어 가능 7~8B 오픈 모델 | M1 Pro 16GB에서 구동 가능한 크기 |
| 외부 공개 | Tailscale Funnel + 인증 프록시 | 무료, 고정 주소, 도메인 불필요 |
| 호스팅 API | Claude Haiku 5.5 (`@anthropic-ai/sdk`) | 저렴하고 빠름, 공식 SDK로 스트리밍 |
| 요청 제한 + 대화 로그 | Upstash Redis (무료 플랜) | 서버리스 환경에 적합, 한 서비스로 두 기능 해결 |
| 배포 | Vercel | Next.js 연동, 프리뷰 배포 |
