### 📱 AI 면접 챗봇 포트폴리오

프로젝트를 소개하고, 면접관이 "이 프로젝트에서 뭘 했나요?"라고 물으면 제가 1인칭으로 답하는 AI 챗봇이 붙은 포트폴리오 웹사이트

### 🛠️ 사용 기술

- 프론트엔드 : Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4
- 콘텐츠 : 마크다운 + frontmatter (gray-matter, Zod로 검증), react-markdown
- 챗봇 : Ollama (gemma4:e4b), Claude API (Haiku 5.5), Tailscale Funnel
- 운영 : Upstash Redis (요청 제한, 대화 로그), Vercel

### 👩‍💻 개발 사항

- Notion 포트폴리오를 마크다운으로 자동 추출하고, 화면과 챗봇이 같은 원본을 쓰도록 구성
- 홈(소개, 핵심 역량, 경력, 사이드 프로젝트)과 프로젝트 상세 페이지 정적 생성, 반응형
- 로컬 LLM과 호스팅 API를 오가는 챗봇 서버 (스트리밍, 자동 전환, 끊김 시 재시도)
- 내 Mac의 Ollama를 외부에 안전하게 공개하기 위한 인증 프록시
- 챗봇 UI: 엔진 전환, 로컬 LLM 상태 표시, 느린 답변 안내, 답변 중단, 추천 질문
- 요청 제한과 대화 로그 저장

### 💡 프로젝트 회고

#### 로컬 LLM + 호스팅 API 하이브리드 구조

> 작업 계기
> - 내 Mac에서 직접 구축한 로컬 LLM으로 답하게 하면 운영 비용이 거의 들지 않음
> - 하지만 Mac이 꺼져 있거나 다른 질문을 처리 중이면 답을 못 하거나 오래 기다려야 함

> 작업 내용
> - 로컬 LLM을 기본으로 쓰고, 로컬이 오프라인이면 Claude Haiku 5.5로 **자동 전환**
> - 로컬 상태는 1.5초 안에 확인하고 결과를 30초 동안 재사용해, 매 질문마다 기다리지 않게 함
> - 로컬 답변 도중 연결이 끊기면 받은 글을 버리고 같은 질문을 클라우드로 다시 요청
> - 두 엔진의 응답을 같은 스트림 형식으로 맞춰, 화면은 엔진 종류와 상관없이 같은 방식으로 그림

> 효과
> - Mac을 덮거나 들고 나가도 챗봇은 계속 동작
> - 메시지마다 어떤 엔진이 몇 초 걸려 답했는지 라벨로 남겨, 하이브리드 구조가 화면에서 바로 보이게 함

#### 로컬 모델 선정

> 작업 내용
> - M1 Pro 16GB에서 돌릴 수 있는 후보 3개(exaone3.5:7.8b, qwen3.5:9b, gemma4:e4b)를 실제 챗봇과 같은 프롬프트로 비교하는 벤치마크 스크립트 작성
> - 같은 질문 12개로 한국어 자연스러움, 사실 정확도, 첫 글자까지 시간, 생성 속도, 메모리, 라이선스를 비교

> 결과
>
> | 모델 | 첫 글자 평균 | 첫 글자 최대 | 생성 속도 | 메모리 | 사실 정확도 |
> | --- | --- | --- | --- | --- | --- |
> | exaone3.5:7.8b | 3.8초 | 16.3초 | 21.5 tok/s | 5.8 GB | React와 React Native를 혼동 |
> | qwen3.5:9b | 11.3초 | 36.7초 | 18.1 tok/s | 7.7 GB | 일부 과장 |
> | gemma4:e4b | 5.0초 | 10.1초 | 25.6 tok/s | 9.4 GB | 가장 정확 |
>
> - 정확도와 속도가 가장 좋은 **gemma4:e4b**로 확정 (메모리를 가장 많이 쓰는 점은 감수)

#### 로컬 LLM을 외부에 공개할 때의 보안

> 문제
> - Ollama에는 자체 인증이 없어서, 그대로 공개하면 누구나 내 Mac의 모델을 쓰거나 다른 모델을 내려받게 할 수 있음

> 작업 내용
> - Mac에 작은 **인증 프록시**를 두고, 비밀키 헤더가 맞는 요청만 채팅·상태 확인 두 경로로 통과시킴 (모델도 고정)
> - Tailscale Funnel로는 프록시만 공개하고, 비밀키는 Vercel 서버에만 두어 브라우저에는 Mac 주소와 키가 드러나지 않게 함
> - 외부에서 직접 확인: 키가 없거나 틀리면 401, Ollama 관리 API는 404, 올바른 키만 200
> - 재부팅해도 프록시가 자동으로 켜지고, 전원 연결 중에는 Mac이 잠들지 않도록 설정

#### 엔진별 컨텍스트 전략

> 작업 계기
> - 로컬 모델은 프롬프트가 길어질수록 첫 글자까지 수십 초가 걸림

> 작업 내용
> - RAG 대신 프로젝트 내용을 시스템 프롬프트에 직접 넣는 방식을 선택 (프로젝트가 11개로 적어 검색이 필요 없음)
> - 호스팅 API에는 전체 프로젝트를 상세히 넣고 프롬프트 캐싱으로 비용을 줄임
> - 로컬 LLM에는 전체 요약 목록 + 관련 프로젝트 1~2개만 상세히 넣음
>   - 상세 페이지에서 연 채팅이면 그 프로젝트, 아니면 최근 질문에 나온 프로젝트명·회사명·기술명으로 고름

#### 지어낸 답변과 규칙 무시 요청 대응

> 문제
> - 1차 벤치마크에서 연봉 질문에 숫자를 지어내고, 자료에 없는 일반론을 덧붙이고, 답변이 길게 나옴

> 작업 내용
> - 자료에 없는 질문과 연봉·처우 질문에는 정해진 문장을 그대로 답하게 함
> - 작은 모델이 긴 자료를 읽고 앞의 규칙을 잊지 않도록, 자료 뒤에 핵심 규칙을 한 번 더 둠
> - 규칙을 바꾸라는 요청(프롬프트 인젝션)은 무시하도록 명시
> - 화면과 같은 원본 콘텐츠에 프로젝트별 팀 구성, 역할, 예상 질문과 답변을 보강해 답변 근거를 늘림

#### 요청 제한과 대화 로그

> 작업 내용
> - 방문자당 분 6회, 일 60회로 요청을 제한해 호스팅 API 비용이 늘어나는 것을 막음
> - 질문, 답변, 엔진, 자동 전환 여부, 응답 시간을 저장해 콘텐츠 보강과 면접 대비에 활용
> - IP는 저장하지 않고 해시값만 저장
> - 로그 저장은 응답이 끝난 뒤 처리해, 저장에 실패해도 답변에는 영향이 없게 함

#### 아쉬운 점

> - 벤치마크에서는 로컬 답변이 평균 7.5초였지만, 외부 공개 경로로 확인했을 때는 40~65초가 걸림
> - 개발 서버와 브라우저를 함께 띄워 메모리가 부족했던 것이 원인으로 보여, 실제 운영 때 다시 측정할 예정
